# 自定义 Agent

到目前为止，你一直在和 Notion 自带的 AI 助手对话——它是一个通用的个人助手，能做很多事，但没有针对你的具体工作流做优化。

现在，是时候认识一个更强大的概念：**自定义 Agent**。它让你创建专属的 AI 助手——有自己的名字、角色、能力和规则，并且可以自动触发。

## 自定义 Agent 是什么

想象一下，你雇了一个专属助理：

- 你可以给它**起个名字**（比如"周报助手""客户分析员"）
- 你可以给它**写一份工作指南**（Instructions），告诉它该做什么、怎么做
- 你可以给它**授权特定的工具**（比如只能访问某个数据库、可以发 Slack 消息）
- 你可以设置**触发条件**（比如每天上午10点自动运行，或数据库新增记录时自动处理）

简单说，自定义 Agent = **指令 + 能力 + 触发器**。

## 创建你的第一个自定义 Agent

> 💬 **你：**
> "帮我创建一个自定义 Agent，名字叫'周报助手'，用于每周生成团队周报"

Agent 会为你创建这个自定义 Agent，包括：
- 一个名字和图标
- 一个指令页面（空的，等待你填写）

创建后，你需要给它配置三样东西：指令、能力、触发器。

## 指令（Instructions）

指令是 Agent 的"工作手册"——一个普通的 Notion 页面，你可以自由编辑。

好的指令应该：

- **从概述开始**：说清楚这个 Agent 的核心任务
- **分步骤说明**：用数字列表描述流程
- **用清晰的标题组织**：方便阅读和维护
- **只写"做什么"，不写"怎么调 API"**：Agent 已经知道怎么用工具，你只需要描述任务和规则

### 示例：周报助手的指令

> 💬 **你：**
> "在周报助手的指令页面里写上以下内容：
> 
> 你是一个团队周报生成助手。每周五下午4点，你需要：
> 1. 查看任务数据库中本周完成的任务
> 2. 查看本周新创建的任务
> 3. 生成一份周报页面，包含：本周完成情况、新增任务、下周计划
> 4. 周报放在'周报归档'页面下面"

## 能力（Integrations）

自定义 Agent 默认**没有任何权限**——这是一个重要的安全设计。你需要显式地告诉它可以访问什么。

能力通过**集成**（Integration）来配置：

| 集成类型 | 描述 | 示例 |
|---------|------|------|
| Notion | 访问工作区页面和数据库 | 读取任务数据库、创建周报页面 |
| Slack | 发送/读取 Slack 消息 | 周报生成后发到频道 |
| GitHub | 访问代码仓库 | 查看 PR 状态 |
| Mail | 发送邮件 | 给客户发送更新 |
| Calendar | 读取日历 | 查看本周会议安排 |

> 💬 **你：**
> "给周报助手加上 Notion 权限，让它能访问任务数据库和周报归档页面。再加上 Slack 集成，让它能在 #team-updates 频道发消息"

> ⚠️ **确定性陷阱 #5：自定义 Agent 默认没有任何权限。** 如果你创建了一个 Agent 但忘了配置权限，它什么都做不了。确保每个 Agent 都有它需要的最小权限。

## 触发器（Triggers）

触发器让 Agent 自动运行——不需要你手动发消息。

### 定时触发

最常用的触发器，按时间表自动运行：

> 💬 "设置周报助手每周五下午4点自动运行"

### 数据库事件触发

当数据库发生变化时自动触发：

> 💬 "当任务数据库中新增记录时，自动让 Agent 检查并填充缺失的属性"

> 💬 "当任务状态改为'已完成'时，自动发一条 Slack 消息通知团队"

### 外部触发

来自连接的外部工具：

> 💬 "当有人在 Slack 里 @ 这个 Agent 时，自动回复"

## Autofill Agent（自动填充 Agent）

这是一类特殊的自定义 Agent，专门用于**批量填充数据库属性**。

### 什么时候用 Autofill Agent

当你需要为数据库中的很多行（超过 20 行）批量填充属性时：

> 💬 **你：**
> "帮我给任务数据库里的所有任务自动生成摘要"

Agent 会为你创建一个 Autofill Agent，专门负责生成摘要。

### 两种模式

| | 基础自动填充 | 自动填充 Agent |
|------|---------|--------|
| **适用场景** | 基于行内已有数据计算 | 需要搜索、联网或定时运行 |
| **示例** | 总结文本、翻译、分类 | 调研竞品、搜索工作区信息 |
| **费用** | 免费 | 消耗 AI 积分 |
| **能力** | 只能用行内数据 | 可搜索、联网、定时触发 |

> 💡 **提示**：如果你只需要基于已有数据做简单计算（比如总结、翻译、分类），基础自动填充就够了，而且完全免费。

## 实际案例

### 案例 1：客户反馈分析员

> 💬 **你：**
> "创建一个自定义 Agent 叫'反馈分析员'。当客户反馈数据库新增记录时，自动：
> 1. 分析反馈内容的情感（正面/中性/负面）
> 2. 提取关键词和主题
> 3. 如果是负面反馈，在 Slack #support 频道发通知"

### 案例 2：会议纪要生成器

> 💬 **你：**
> "创建一个 Agent 叫'会议助手'。给它 Notion 和 Calendar 的权限。当我在对话中 @ 它时，它查看我今天的会议安排，然后为每个会议创建一个笔记页面，预填好会议主题和参会人"

### 案例 3：批量翻译

> 💬 **你：**
> "我的内容数据库有 200 条记录，每条都有一个'中文描述'属性。帮我创建一个自动填充 Agent，自动把中文描述翻译成英文，填到'英文描述'属性里"

Agent 会创建一个基础自动填充 Agent（免费），因为翻译只需要行内数据。

## 自定义 Agent vs 个人助手

你可能会问：我直接和个人助手聊不就行了吗，为什么还要创建自定义 Agent？

| | 个人助手 | 自定义 Agent |
|------|---------|--------|
| **触发** | 你手动发消息 | 可自动触发 |
| **指令** | 每次都要说 | 写一次，永久生效 |
| **权限** | 跟你的权限一样 | 精确控制，最小权限 |
| **分享** | 只有你能用 | 可分享给团队成员 |
| **适用场景** | 临时任务 | 重复性工作流 |

简单说：如果一件事你要重复做，或者需要自动化，就值得创建自定义 Agent。

## 实用技巧

### 先写好指令再配置其他

指令是 Agent 的灵魂。一个精心编写的指令页面能让 Agent 的行为更可预测。

### 指令里只写"做什么"

Agent 已经知道怎么操作 Notion、怎么发 Slack 消息。你不需要在指令里写技术细节（API 名称、函数调用等），只需要描述业务规则。

> ✅ "查看任务数据库中本周完成的任务"
> ❌ "call querySql with SELECT * FROM tasks WHERE status = 'Done'"

### 配置后记得测试

每次修改 Agent 的指令、权限或触发器后，建议跑一次测试确认效果。你可以直接让个人助手帮你测试：

> 💬 "帮我测试一下周报助手，看它能不能正确生成周报"

### 最小权限原则

只给 Agent 它需要的权限，不要给多余的。这样更安全，也更容易排查问题。

## 本章小结

- **自定义 Agent** = 指令 + 能力（集成）+ 触发器
- **指令**是一个 Notion 页面，描述 Agent 该做什么，不需要写技术细节
- **集成**给 Agent 授权特定工具（Notion、Slack、GitHub 等），默认无权限
- **触发器**让 Agent 自动运行（定时、数据库变更、外部事件）
- **Autofill Agent** 专门用于批量填充数据库属性，分基础（免费）和完整两种模式
- 配置变更后必须测试
- 重复性工作流适合用自定义 Agent，临时任务用个人助手就行

下一章，我们进一步探索 Agent 如何与外部工具连接和協作。

---

> 📌 **本章盲区声明**：自定义 Agent 的可用性取决于你的 Notion 计划等级。Autofill Agent 的完整模式需要消耗 AI 积分，具体费用取决于使用量。触发器的类型和外部集成的可用性可能随 Notion 版本更新而扩展。
