# 你的第一次对话

上一章我们了解了 Notion Agent 是什么、能做什么。现在，是时候动手了。

本章会带你完成第一次与 Agent 的真实对话——从打开对话框开始，到让 Agent 帮你创建页面、搜索信息，再到理解对话背后的运作机制。读完这一章，你就能独立和 Agent "聊起来"了。

## 打开对话框

找到 Agent 的入口很简单：

- **桌面端 / 网页端**：点击屏幕右下角的小圆脸图标，或者在左侧栏打开"Notion AI"标签页
- **移动端**：点击底部的"Notion AI"入口

点开后，你会看到一个对话框——这就是你和 Agent 沟通的唯一窗口。你可能还会看到几个快捷操作按钮（比如"新建页面""帮我总结""创建图片""头脑风暴"），但别急着点，我们先从最基本的开始。

> 💡 **提示**：如果你在移动端，还可以点击顶部菜单切换 AI 模型。Notion Agent 支持多家厂商的模型（OpenAI、Anthropic 等），你可以根据偏好选择。

## 第一句话："帮我创建一个页面"

现在，试着在对话框里输入：

> 💬 **你对 Agent 说：**
> "帮我创建一个读书笔记页面，标题叫《三体》读书笔记"

几秒钟后，Agent 会回复你，告诉你页面已经创建好了。你会在回复中看到一个指向新页面的链接——点击就能跳转过去。

> 🤖 **Agent 会做的事：**
> 1. 确定页面的位置——因为你没指定，它会把页面创建在你的个人空间里（顶层私人页面）
> 2. 设置标题为"《三体》读书笔记"
> 3. 可能还会贴心地加个图标（比如 📖）
> 4. 返回一个链接给你

就这么简单。你说了一句话，Agent 就在你的工作区里创建了一个真实的页面。

### 如果你想要更具体的页面

你可以在同一个对话里继续说：

> 💬 **你：**
> "帮我在这个页面里加上这些内容：一个二级标题'核心概念'，下面列三个要点：黑暗森林法则、猜疑链、技术爆炸"

Agent 会找到你刚才创建的页面（因为它还"记得"那个页面的地址），然后直接编辑页面内容。你不需要告诉它页面在哪里——这就是**对话上下文**的威力，我们马上会详细讲。

## 第二句话："帮我搜点东西"

创建页面很酷，但 Agent 的另一项核心能力是搜索。试试这个：

> 💬 **你：**
> "搜索一下我工作区里有没有关于项目管理的页面"

> 🤖 **Agent 会做的事：**
> 1. 调用搜索功能，在你的 Notion 工作区中查找与"项目管理"相关的内容
> 2. 如果你连接了 Slack、Google Drive 等外部工具，也可能从那里找到结果
> 3. 把搜索结果整理好，用自然语言告诉你找到了什么

Agent 的搜索不是简单的关键词匹配——它理解语义。如果你的工作区里有一个叫"Q3 Sprint Planning"的页面，搜"项目管理"也可能找到它。

> ⚠️ **注意**：Agent 的搜索默认也包含互联网结果。如果你只想搜自己的工作区，可以明确说"只在我的工作区里搜索"。

## 对话背后发生了什么

到目前为止，你已经体验了 Agent 的两个基本操作：创建页面和搜索。但你可能好奇：Agent 是怎么做到的？

答案是：**工具调用**（Tool Calling）。

每当你对 Agent 说一句话，Agent 实际上会经历以下过程：

1. **理解意图**：分析你说的话，判断你想要什么
2. **选择工具**：从它掌握的几十个工具中，选择合适的来完成任务
3. **调用工具**：执行操作（比如调用 `createPage` 创建页面）
4. **整理结果**：把工具返回的结果翻译成你能理解的自然语言

这个过程是透明的——Agent 会在回复中告诉你它做了什么。

为什么这个知识重要？因为它解释了两件事：

- **为什么 Agent 有时候比你预期的慢**：它不只是在"想"，还在"做"——每次工具调用都需要时间
- **为什么对话越长 Agent 越容易"失忆"**：每次工具调用的输入和输出都会占用对话的记忆空间

## Thread：你的对话容器

现在来认识一个重要概念：**Thread**（对话线程）。

把 Thread 想象成**一通电话**。你拨通电话后，双方的对话是连续的——你说的每句话，对方都能听到并记住。挂了电话，这通对话就结束了。下次打电话，是一通全新的通话。

Thread 的工作方式完全一样：

- **一个 Thread = 一次对话**：从你发第一条消息开始，到你关闭对话或开始新对话为止
- **Thread 内有记忆**：Agent 记得你在这个 Thread 里说过的所有话、做过的所有操作
- **Thread 间无记忆**：开一个新 Thread，Agent 就像换了一个人——它不记得上一通"电话"的内容

### 上下文：Thread 里最重要的机制

在一个 Thread 中，Agent 能"看到"的所有信息统称为**上下文**（Context）。它包括：

- 你和 Agent 的所有对话内容
- Agent 每次工具调用的输入和输出
- 系统预加载的信息（你的用户信息、工作区名称、当前时区等）

上下文是 Agent 工作的基础。比如前面的例子——你让 Agent 创建页面，然后让它编辑同一个页面。Agent 之所以知道要编辑哪个页面，是因为创建页面时工具返回了一个页面地址（URL），这个地址就留在了上下文里。

### 上下文的大小是有限的

这里有一个关键限制：上下文有容量上限。就像你的手机内存一样——存的东西太多就会变慢，甚至丢失早期的内容。

具体来说：

- 每条消息、每次工具调用的输入和输出，都在消耗上下文空间
- **工具调用比纯聊天消耗更多空间**——因为工具的输入参数和返回结果往往很长
- 当上下文接近上限时，最早的对话内容会被截断——Agent 就"忘记"了

> ⚠️ **确定性陷阱 #1：对话过长，Agent 会失忆。** 如果你在一个 Thread 里做了大量操作（创建了十几个页面、搜索了很多次），Agent 可能忘记早期的操作细节。解决方案很简单：**开一个新 Thread**。

### 跨 Thread 的"记忆"

你可能会问：如果每个 Thread 都是独立的，Agent 怎么记住我的偏好？

答案是：Notion 有一个叫 **System Memories** 的机制。系统会根据你的使用历史自动生成一些背景摘要，在新 Thread 启动时预加载给 Agent。

但要注意——这种记忆是**模糊的**：

- 它是系统自动总结的，不是逐字记录
- 你看不到也控制不了它的内容
- 它可能遗漏重要细节

所以，如果有重要的偏好或规则想让 Agent 始终遵守，不要依赖 System Memories。更好的方式是使用 **Instructions**（指令页面）——一个专门的 Notion 页面，写下你对 Agent 的长期指令。Agent 每次开新 Thread 都会读取它。

> 💡 **实用建议**：在你的 Instructions 页面里写上你的常用偏好。比如："创建页面时默认使用中文""搜索时优先搜索我的工作区"。这比期待 Agent 自己"记住"要可靠得多。

## 试试连续操作

现在你理解了 Thread 和上下文，来试试一个稍微复杂的场景：

> 💬 **你（第一步）：**
> "帮我创建一个项目计划页面，标题是'Q3 产品规划'"

Agent 创建好页面，返回链接。

> 💬 **你（第二步）：**
> "在这个页面里加一个表格，三列：里程碑、负责人、截止日期"

Agent 找到刚才的页面（URL 还在上下文里），在页面内插入表格。

> 💬 **你（第三步）：**
> "把这个页面移到'团队空间'下面"

Agent 修改页面的父级位置，将其移到你指定的 Teamspace 里。

三步操作，全在同一个 Thread 里完成。Agent 从头到尾都知道你在操作哪个页面——因为上下文把一切串起来了。

## @ 提及：告诉 Agent 你在说哪个页面

有时候你想操作的页面不是刚创建的，而是工作区里已经存在的某个页面。这时候可以用 **@ 提及**：

在对话框里输入 `@`，Notion 会弹出一个搜索框，让你选择一个页面或数据库。选中后，这个页面的地址就会传给 Agent。

> 💬 **你：**
> "帮我在 @周报模板 页面的末尾加一段'本周计划'的内容"

> 🤖 **Agent 会做的事：**
> 1. 从 @ 提及中拿到"周报模板"页面的地址
> 2. 加载这个页面的内容（这是一个额外步骤——@ 只给地址，不给内容）
> 3. 在页面末尾添加你要求的内容

> ⚠️ **确定性陷阱 #2：@ 提及不等于加载内容。** 当你 @ 一个页面时，Agent 只拿到了页面的地址和标题。如果它需要知道页面里写了什么才能完成任务，它得再跑一步去加载内容。这意味着涉及已有页面内容的操作可能比你预期的多花一两秒。

## Agent 每次开工前都知道什么

你可能好奇：每次开始新对话时，Agent 是"一张白纸"吗？

不完全是。每个新 Thread 启动时，系统会自动给 Agent 预加载一些信息：

- **你是谁**：你的名字、邮箱、用户 ID
- **你在哪个工作区**：工作区名称
- **你在看什么**：你当前打开的页面（如果有的话）
- **你的时区**：用于处理日期和时间
- **你的个性化设置**：你的 Instructions 页面内容、已配置的 Skills
- **你连接了哪些工具**：Slack、Google Drive、GitHub 等

这就是为什么 Agent 一上来就知道你的名字，也知道你的工作区里有哪些连接——它不是在"偷看"，是系统主动告诉它的。

## 什么时候该开新 Thread

一个简单的判断标准：

- **继续用当前 Thread**：你还在做同一件事，或者需要引用之前的操作结果
- **开一个新 Thread**：你要做一件完全不同的事，或者感觉 Agent 开始"忘事"了

每个 Thread 都是独立的，开新 Thread 没有任何成本。如果拿不准，开新的通常不会错。

## 本章小结

- 打开对话框：点击右下角圆脸图标，或在左侧栏找到"Notion AI"
- **Thread** 是一次对话的容器，就像一通电话——通话中有记忆，挂了就没了
- **上下文**是 Thread 里所有信息的总和（对话 + 工具调用 + 预加载信息），是 Agent 工作的基础
- 上下文有大小限制——对话过长 Agent 会"失忆"，解决方案是开新 Thread
- **@ 提及**可以告诉 Agent 你要操作哪个页面，但它只传地址，不传内容
- 跨 Thread 的长期记忆靠 System Memories 和 Instructions 页面——后者更可靠
- Agent 每次开工前已经知道你是谁、在哪个工作区、连了哪些工具
