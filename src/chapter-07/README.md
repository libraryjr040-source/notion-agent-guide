# 外部连接与集成

Notion Agent 的真正威力，在于它不仅能操作 Notion 工作区，还能连接外部世界。通过**连接**（Connections），Agent 可以读写 Slack、搜索 Google Drive、查看 GitHub PR、收发邮件，甚至调用自定义的 MCP 服务器。

本章带你了解如何管理这些连接，以及它们能做什么。

## 连接是什么

连接是 Agent 与外部服务之间的桥梁。每个连接代表一个已授权的服务通道：

- **Slack 连接** → Agent 可以读取和发送 Slack 消息
- **GitHub 连接** → Agent 可以查看仓库、PR、Issue
- **邮件连接** → Agent 可以收发邮件
- **日历连接** → Agent 可以查看日程安排

## 查看和管理连接

### 查看已有连接

> 💬 **你：**
> "我现在有哪些连接？"

Agent 会列出你所有已激活的连接，以及它们的状态：
- **已就绪**（ready）：正常工作
- **需要连接**（needs_connection）：需要重新授权
- **需要权限**（needs_permissions）：授权不完整

### 添加新连接

> 💬 **你：**
> "帮我连接 Slack"

Agent 会发起连接流程。你只需要在弹出的授权页面中确认即可。

## 可用的连接类型

### Notion 原生连接

| 连接 | 说明 |
|------|------|
| **Notion Mail** | Notion 的邮件功能，可收发邮件 |
| **Notion Calendar** | Notion 的日历功能，可查看日程 |

> 💡 当你说"连接邮件"或"连接日历"时，Agent 默认使用 Notion 原生的 Mail 和 Calendar，而不是 Gmail 或 Google Calendar。这是推荐的方式。

### 第三方服务

| 连接类型 | 典型用途 |
|---------|--------|
| **Slack** | 读取/发送消息、监听 @提及 |
| **GitHub** | 查看仓库、PR、Issue |
| **Jira** | 查看和管理工单 |
| **Linear** | 查看和管理任务 |
| **Asana** | 查看和管理项目 |
| **Discord** | 读取/发送 Discord 消息 |
| **Microsoft Teams** | 读取/发送 Teams 消息 |

### 文档与存储

| 连接类型 | 典型用途 |
|---------|--------|
| **Google Drive** | 搜索和读取 Google 文档 |
| **Confluence** | 搜索和读取 Confluence 页面 |
| **SharePoint** | 搜索和读取 SharePoint 文档 |
| **Box** | 搜索和读取 Box 文件 |

### 邮件与日历（替代方案）

| 连接类型 | 说明 |
|---------|------|
| **Gmail** | Google 邮箱（如不用 Notion Mail） |
| **Outlook** | Microsoft 邮箱（如不用 Notion Mail） |
| **Google Calendar** | Google 日历（如不用 Notion Calendar） |

### 高级连接

| 连接类型 | 说明 |
|---------|------|
| **Salesforce** | CRM 数据 |
| **MCP 服务器** | 自定义工具服务器（下文详述） |
| **Worker** | 自定义 Worker 连接 |

## MCP 服务器

MCP（Model Context Protocol）是一种标准协议，让 Agent 能够调用外部工具。通过 MCP 服务器，你可以把几乎任何外部服务接入 Agent。

### 连接 MCP 服务器

> 💬 **你：**
> "帮我连接 Figma MCP 服务器"

Agent 会查找可用的 MCP 服务器列表，并帮你连接。

### MCP 服务器能做什么

连接后，你可以让 Agent 使用 MCP 服务器提供的工具。比如连接了 GitHub MCP 后：

> 💬 **你：**
> "用 GitHub 帮我创建一个新仓库，名字叫 my-project"

> 💬 **你：**
> "查看 my-project 仓库的最近 PR"

MCP 服务器提供的具体工具取决于服务器本身。你可以让 Agent 列出可用工具：

> 💬 **你：**
> "GitHub MCP 有哪些可用工具？"

## 搜索连接源

在第五章我们学过，搜索功能可以跨所有已连接的源进行搜索。这是连接的一个重要价值——你的信息不再孤立在各个工具里。

> 💬 **你：**
> "在 Slack 里搜索关于产品发布的讨论"

> 💬 **你：**
> "搜索 Google Drive 里的季度报告"

Agent 会自动在对应的连接源中搜索，并返回带链接的结果。

## Web 访问

除了已连接的服务，Agent 还可以直接访问公开网页。

### 网页搜索

> 💬 **你：**
> "搜索一下 Notion API 的最新文档"

### 加载网页内容

> 💬 **你：**
> "帮我读一下这个网页的内容：https://example.com/article"

Agent 会抓取网页文本，你可以基于内容继续讨论或提取信息。

> 💡 **提示**：Agent 会先尝试快速抓取。如果内容不完整，它会自动切换到更彻底的抓取模式（可能需要更长时间）。

## 通知

Agent 可以向你发送 Notion 通知：

> 💬 **你：**
> "提醒我明天下午3点检查周报"

通知会出现在你的 Notion 收件箱中。

## 自定义 Agent 的连接 vs 个人助手的连接

这是一个重要的区分：

| | 个人助手 | 自定义 Agent |
|------|---------|--------|
| **连接来源** | 你的个人连接设置 | Agent 配置中的集成 |
| **管理方式** | 通过对话添加/查看 | 在 Agent 配置中设置 |
| **权限范围** | 跟随你的权限 | 精确控制，最小权限 |
| **添加方式** | "帮我连接 Slack" | "给这个 Agent 加上 Slack 集成" |

对于个人助手，连接是你直接管理的；对于自定义 Agent，连接是通过集成配置的（见第六章）。

## Agent 之间的协作

Agent 不仅能连接外部服务，还能互相调用：

> 💬 **你：**
> "让周报助手帮我生成本周的周报"

个人助手可以调用你创建的自定义 Agent，让它们各司其职。这就像一个团队——你作为管理者，个人助手作为协调者，各个自定义 Agent 作为专业执行者。

> ⚠️ **注意**：自定义 Agent 之间的互相调用需要明确的授权配置。个人助手可以调用任何你有权限的自定义 Agent，但自定义 Agent 只能调用被授权的其他 Agent。

## 实际案例

### 案例 1：跨工具信息汇总

> 💬 **你：**
> "帮我看看今天的情况：
> - Notion 里有哪些任务到期
> - Slack 里 #team 频道有什么重要消息
> - 日历上接下来有什么会议"

Agent 会依次查询各个连接源，汇总信息给你。

### 案例 2：GitHub PR 跟踪看板

> 💬 **你：**
> "创建一个自定义 Agent 叫 'PR 跟踪器'。给它 GitHub 和 Notion 权限。每天早上9点，让它检查所有打开的 PR，然后更新我的 PR 跟踪数据库"

这里用到了：自定义 Agent + GitHub 集成 + Notion 集成 + 定时触发器。

### 案例 3：邮件摘要

> 💬 **你：**
> "帮我看看最近的邮件里有没有关于合同的内容"

Agent 通过邮件连接搜索你的收件箱。

## 实用技巧

### 先连接，再使用

如果你让 Agent 做某件需要外部服务的事（比如"在 Slack 里发消息"），但还没有连接 Slack，Agent 会提示你先建立连接。建议提前连接好常用的服务。

### 搜索时指定来源

当你想在特定平台搜索时，明确说出来：

- ✅ "在 Slack 里搜索关于部署的讨论"
- ✅ "搜索 Google Drive 里的设计文档"
- ❌ "搜索关于部署的内容"（Agent 会在所有源中搜索，可能不是你想要的）

### 理解连接状态

如果某个连接不工作了，可能是授权过期。让 Agent 检查连接状态：

> 💬 "检查一下我的连接状态，看看有没有需要重新授权的"

## 本章小结

- **连接**是 Agent 访问外部服务的桥梁，通过对话即可添加和管理
- **Notion Mail 和 Calendar** 是推荐的邮件和日历连接方式
- **MCP 服务器**可以接入自定义工具，极大扩展 Agent 能力
- **搜索**可以跨所有已连接的源进行，打破信息孤岛
- **个人助手的连接**和**自定义 Agent 的集成**是两套不同的体系
- **Agent 之间可以协作**，个人助手可以调度自定义 Agent

下一章，我们将分享使用 Notion Agent 的高级技巧和最佳实践。

> 📌 **本章盲区声明**：可用的连接类型和 MCP 服务器可能随 Notion 版本更新而增加。某些连接类型可能需要特定的 Notion 计划等级。MCP 服务器的具体工具取决于服务器实现方，不在本书覆盖范围内。
