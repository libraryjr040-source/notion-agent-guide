# Notion Agent 是什么

想象一下：你打开 Notion，在右下角看到一个小圆脸图标。点开它，一个对话框弹出来。你输入一句话——"帮我创建一个读书笔记页面"——几秒钟后，一个带着标题、图标和初始结构的页面就出现在你的工作区里了。

这不是普通的聊天机器人。这是 **Notion Agent**——一个住在你 Notion 工作区里的 AI 助理，它不只会说话，还会动手。

## 不只是聊天，而是动手干活

你可能用过 ChatGPT、Claude 或其他 AI 聊天工具。它们很强大，但有一个共同的局限：它们只能给你文字回复。你问它"帮我建一个项目管理表格"，它会告诉你怎么建，但你得自己动手。

Notion Agent 不一样。它能**直接操作你的工作区**：

- 你说"创建一个页面"，它就真的创建了一个页面
- 你说"在数据库里加一个状态属性"，它就真的加了
- 你说"帮我搜一下上周的会议记录"，它就真的去搜了，而且不只搜 Notion——如果你连接了 Slack、Google Drive，它也能搜

> ⚠️ **第一个重要认知：Agent 能真实修改你的工作区。** 如果你让它删除一个页面，它会真的删除。这意味着 Agent 很强大，但也意味着你需要知道它的能力边界。

## Agent 能做什么：能力全景图

把 Agent 想象成一个**私人助理**。这个助理住在你的 Notion 办公室里，你可以随时跟它说话，让它帮你干活。它的能力可以分为以下几大类：

### 📄 页面操作

这是 Agent 最基础也最常用的能力。它可以：

- **创建页面**——在工作区任意位置创建新页面
- **编辑内容**——修改页面中的文字、标题、列表、表格等
- **管理属性**——设置页面标题、图标、状态等
- **移动页面**——把页面从一个位置挪到另一个位置
- **归档和删除**——把不需要的页面归档或移到垃圾箱

### 🗄️ 数据库操作

如果说页面是 Notion 的基础，数据库就是 Notion 的灵魂。Agent 可以：

- **创建数据库**——从零开始设计数据库结构
- **设计属性**——添加各种类型的属性（文本、数字、选择、日期、关联等 25+ 种）
- **配置视图**——创建表格、看板、日历、时间线等不同展示方式
- **查询数据**——用类似 SQL 的语法精确查找数据
- **批量更新**——修改数据库中的页面属性

### 🔍 搜索

Agent 的搜索能力远超你的想象。它不只搜 Notion：

- **Notion 工作区**——你的所有页面和数据库
- **连接的应用**——Slack 消息、Google Drive 文档、GitHub 代码、Jira 工单等
- **互联网**——需要时也能搜索网页

### 🤖 Agent 管理

Agent 不只能帮你干活，还能帮你"雇佣"新的助理：

- **创建 Custom Agent**——针对特定任务创建专职 Agent
- **配置自动化**——让 Agent 在特定事件发生时自动执行任务
- **批量填充**——创建 Autofill Agent 来批量处理数据库中的数据

### 🔌 外部工具

通过 MCP（Model Context Protocol），Agent 可以调用外部服务：

- **GitHub**——查看仓库、提交代码、管理 Issue
- **其他 MCP 服务**——任何实现了 MCP 协议的工具

### 📊 其他能力

- **发送通知**——在 Notion 内发送提醒
- **分析数据**——查看工作区的使用分析
- **会议笔记**——查询和处理会议记录
- **子线程**——派出"分身"去并行处理多个任务

## Agent 不能做什么：能力边界

知道 Agent 能做什么很重要，知道它**不能做什么**同样重要。以下是 Agent 的明确边界：

### ❌ 工作区管理操作

Agent 不能更改工作区的管理设置：

- 不能修改成员角色和权限策略
- 不能管理账单和订阅
- 不能配置安全设置和域名
- 不能调整工作区级别的偏好设置

这些操作需要你作为工作区管理员在 Notion 设置界面中手动完成。

### ❌ 访问未授权的内容

Agent 遵守 Notion 的权限体系。如果你没有某个页面的访问权限，Agent 也无法帮你访问。这是一个重要的安全设计——Agent 是你的助理，不是超级管理员。

### ❌ 主动联系外部人员

Agent 不能帮你发邮件、发微信或在外部平台上联系别人。它可以在 Notion 内发送通知，但仅限于此。

### ❌ 持续后台运行（Personal Agent）

你的 Personal Agent 只在你和它对话时才"存在"。关掉对话窗口，它就休息了。不过，Custom Agent（后面会讲到）可以通过触发器在特定事件发生时自动运行。

## 快速认识几个核心概念

在深入学习 Agent 的各种操作之前，你需要对 Notion 的核心概念有一个基本认识。这里不会深入讲解——后续章节会逐一展开——但你需要知道这些"积木"的名字和大致用途。

### Workspace（工作区）——你的共享办公室

**Workspace** 是 Notion 的顶层空间。你可以把它想象成一间共享办公室：里面有各种页面（文档）、数据库（文件柜）、成员（同事），以及各种权限设置。

你的所有 Notion 内容都生活在某个 Workspace 里。Agent 也住在这里——它能看到你能看到的一切，也只能操作你有权限操作的内容。

### Page（页面）——万能的乐高底板

**Page** 是 Notion 最基础的构建单元。把它想象成一块乐高底板：

- 你可以在上面放文字、图片、表格、代码块等各种"积木"
- 你可以在一个页面里嵌套另一个页面（子页面）
- 你甚至可以在页面里放一个数据库

但页面不只是文档。当一个页面被放进数据库时，它就变成了数据库中的"一行数据"——同时拥有内容（正文）和属性（状态、标签、日期等结构化字段）。这个双重身份是 Notion 独特的设计，我们会在第三章和第四章详细讲解。

### Database（数据库）——智能文件柜

**Database** 是 Notion 中管理结构化信息的工具。把它想象成一个智能文件柜：

- 柜子里的每个文件夹就是一个页面
- 每个文件夹上贴着各种标签（属性）
- 你可以按不同方式查看这个柜子里的内容——像表格一样看、像看板一样看、像日历一样看

数据库是 Notion 的灵魂功能之一。第四章会专门用一整章来讲解如何用 Agent 操作数据库。

### Teamspace（团队空间）——办公室里的会议室

**Teamspace** 是 Workspace 内部的独立分区。就像办公室里的会议室——有自己的门禁和成员名单。不同团队可以在各自的 Teamspace 里工作，互不打扰。

## Personal Agent 和 Custom Agent

你可能注意到前面提到了两种 Agent。这里先建立一个基本概念：

### Personal Agent：你的私人助理

每个 Notion 用户都有且只有一个 **Personal Agent**。它是你的通用助理：

- 继承你的权限——你能看到的，它都能看到
- 能使用你连接的所有工具——Slack、Google Drive、GitHub 等
- 通过 Instructions（指令页面）和 Skills（技能）个性化
- 只在你和它对话时才工作

### Custom Agent：你雇佣的专职员工

**Custom Agent** 是你可以创建的专职 Agent。它和 Personal Agent 有几个关键区别：

- **默认没有任何权限**——创建后什么都不能做，你必须一项一项授予它需要的权限。这叫"最小权限原则"
- **有独立的指令页面**——你可以精确描述它应该做什么
- **可以自动运行**——通过触发器（定时、事件驱动等）自动执行任务
- **可以共享**——团队成员都可以使用

> ⚠️ **第二个重要认知：Custom Agent 默认没有任何权限。** 创建一个 Custom Agent 后，如果你不给它配置权限，它什么都做不了。这是一个安全设计，不是 Bug。

我们会在第六章详细讲解如何创建和配置 Custom Agent。

## 本章小结

- **Notion Agent** 是住在你 Notion 工作区里的 AI 助理，它能直接操作你的页面、数据库，搜索信息，甚至调用外部工具
- Agent **不只是聊天**——它能真实地创建、修改、删除你工作区中的内容
- Agent 有**明确的边界**：不能做管理操作、不能访问未授权内容、不能主动联系外部人员
- **Personal Agent** 是你的通用助理（每人一个），**Custom Agent** 是可创建的专职角色（默认无权限）
- Notion 的核心构建单元是 **Workspace**（办公室）、**Page**（乐高底板）、**Database**（智能文件柜）和 **Teamspace**（会议室）
