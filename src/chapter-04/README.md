# 数据库操作

如果页面是 Notion 的基本单位，那么数据库就是 Notion 最强大的结构化数据工具。它把一堆页面组织成表格、看板、日历、图表等各种形式——本质上，数据库就是**带结构的页面集合**。

## 什么是数据库

想象一个 Excel 表格：每一行是一条记录，每一列是一个属性（字段）。Notion 数据库类似，但有两个关键区别：

1. **每行都是一个页面**——你可以点进去写详细内容
2. **同一份数据可以用多种视图展示**——表格、看板、日历、图表等随时切换

数据库由三个核心部分组成：

- **数据源（Data Source）**：定义属性结构（有哪些列、每列是什么类型）
- **视图（View）**：决定数据怎么展示（表格？看板？日历？）
- **页面（Page）**：每条数据记录

## 创建数据库

### 最简单的方式

> 💬 **你：**
> "帮我创建一个任务管理数据库，包含：标题、状态（未开始/进行中/已完成）、负责人、截止日期"

Agent 会创建一个包含上述属性的数据库，默认展示为表格视图。

### 指定更多细节

你可以一次性描述得很详细：

> 💬 **你：**
> "在 @项目文档 下面创建一个 Bug 追踪数据库，属性包括：
> - 标题
> - 严重程度（选择：P0/P1/P2/P3）
> - 状态（未处理/修复中/已修复/已关闭）
> - 负责人
> - 报告日期
> - 相关功能（多选：登录/支付/搜索/通知）
> 
> 视图：一个表格视图显示所有 Bug，一个看板视图按严重程度分组"

Agent 会创建数据库、定义所有属性、配置两个视图——一步到位。

## 属性类型

属性是数据库的骨架。Notion 支持丰富的属性类型，以下是最常用的：

### 基础属性

| 类型 | 用途 | 示例 |
|------|------|------|
| 标题（Title） | 每条记录的名称，必有 | "修复登录 Bug" |
| 文本（Text） | 自由文本 | 备注、描述 |
| 数字（Number） | 数值，支持货币/百分比 | 金额、评分、进度 |
| 日期（Date） | 日期或日期范围 | 截止日期、事件时间 |
| 复选框（Checkbox） | 是/否 | 是否完成 |

### 选择类属性

| 类型 | 用途 | 示例 |
|------|------|------|
| 单选（Select） | 从预设选项中选一个 | 优先级：高/中/低 |
| 多选（Multi-select） | 选多个标签 | 标签：前端、后端、设计 |
| 状态（Status） | 带工作流分组的选择 | 未开始 → 进行中 → 完成 |

**状态属性**比普通选择多了一个维度：**分组**。每个选项必须属于以下分组之一：
- **待办（To Do）**：还没开始
- **进行中（In Progress）**：正在做
- **完成（Complete）**：已经做完

这让 Notion 知道你的工作流走向，在看板视图中特别有用。

### 关系类属性

| 类型 | 用途 | 示例 |
|------|------|------|
| 人员（Person） | 关联工作区成员 | 负责人、审核人 |
| 关联（Relation） | 连接另一个数据库 | 任务 ↔ 项目 |
| 汇总（Rollup） | 聚合关联数据 | 统计项目下未完成任务数 |

### 自动属性

| 类型 | 用途 |
|------|------|
| 创建时间 | 自动记录创建时间 |
| 最后编辑时间 | 自动记录最后修改时间 |
| 创建人 | 自动记录创建者 |
| 最后编辑人 | 自动记录最后修改者 |
| 自增 ID | 自动编号 |

### 高级属性

| 类型 | 用途 | 示例 |
|------|------|------|
| 公式（Formula） | 基于其他属性计算 | 距截止日期还有几天 |
| 地点（Place） | 存储地理位置 | 办公室地址（配合地图视图） |

## 视图：同一份数据，多种展示

这是 Notion 数据库最强大的特性——同一份数据可以通过不同视图呈现：

### 表格视图（Table）

最经典的电子表格形式，适合查看和编辑大量数据。

> 💬 "给数据库加一个表格视图，显示标题、状态和截止日期三列"

### 看板视图（Board）

像 Trello 一样的卡片墙，按某个属性分组。

> 💬 "加一个看板视图，按状态分组"

看板视图需要指定一个**分组属性**（通常是 Status 或 Select 类型）。

### 日历视图（Calendar）

按日期展示，适合排期和规划。

> 💬 "加一个日历视图，按截止日期显示"

### 列表视图（List）

简洁的清单形式。

> 💬 "加一个列表视图，只显示标题和状态"

### 画廊视图（Gallery）

卡片形式，适合展示带封面图的内容。

> 💬 "加一个画廊视图，显示封面图"

### 时间线视图（Timeline）

甘特图形式，适合项目规划。

> 💬 "加一个时间线视图，按开始日期到截止日期显示"

### 图表视图（Chart）

数据可视化，支持柱状图、折线图、饼图（环形图）和数字卡片。

> 💬 "加一个柱状图，按状态统计任务数量"
> 
> 💬 "加一个饼图，按优先级分布"

### 地图视图（Map）

在地图上展示带地点属性的数据。

> 💬 "加一个地图视图，按办公地点显示"

### 表单视图（Form）

收集数据的表单，类似 Google Forms。

> 💬 "创建一个表单视图，收集 Bug 报告，必填字段包括标题和严重程度"

### 仪表盘视图（Dashboard）

把多个图表和视图组合在一起，形成数据看板。

> 💬 "创建一个仪表盘，上面放任务数量统计和按状态分布的饼图，下面放一个表格显示未完成任务"

## 查询数据

Agent 可以帮你从数据库中查找特定的数据：

### 简单查询

> 💬 **你：**
> "帮我查一下任务数据库里状态为'进行中'的所有任务"

Agent 会查询数据库并返回结果。

### 复杂查询

> 💬 **你：**
> "统计一下 Bug 数据库里每个严重程度各有多少个未修复的 Bug"

Agent 可以执行更复杂的查询，包括过滤、分组和统计。

### 跨数据库查询

如果两个数据库之间有关联属性，Agent 可以做跨库查询：

> 💬 **你：**
> "查一下张三负责的所有项目中，还有多少未完成的任务"

## 关联数据库

### 单向关联

最简单的关联——在一个数据库里添加一个指向另一个数据库的属性：

> 💬 **你：**
> "在任务数据库里加一个'所属项目'属性，关联到项目数据库"

### 双向关联

更强大的关联——两个数据库互相引用：

> 💬 **你：**
> "创建任务和项目之间的双向关联：任务里有'所属项目'，项目里有'关联任务'"

Agent 会在两个数据库中各创建一个关联属性，互相指向对方。这样你在项目页面可以看到所有关联的任务，反之亦然。

### 汇总（Rollup）

有了关联之后，可以用汇总属性来聚合关联数据：

> 💬 **你：**
> "在项目数据库里加一个'未完成任务数'属性，统计关联任务中状态不是'已完成'的数量"

## 链接数据库（Linked Database）

有时你想在不同的页面展示同一个数据库的数据——比如在项目页面只展示该项目的任务。这就是链接数据库：

> 💬 **你：**
> "在 @Q3规划 页面嵌入一个任务数据库的链接视图，只显示 Q3 相关的任务"

Agent 会创建一个链接数据库——它不复制数据，而是引用原始数据源，只是用不同的视图和过滤条件展示。

## 修改数据库

### 添加属性

> 💬 "在任务数据库里加一个'优先级'单选属性，选项是高/中/低"

### 修改视图

> 💬 "把看板视图的分组改为按优先级分组"

### 添加过滤和排序

> 💬 "给表格视图加一个过滤器，只显示负责人是我的任务，按截止日期升序排列"

## 实用技巧

### 一次性描述完整的数据库结构

和创建页面一样，创建数据库也推荐一次说清楚：

> ✅ 推荐：
> "创建一个项目管理数据库，属性：标题、状态（规划中/进行中/已上线）、负责人、开始日期、截止日期、优先级（P0/P1/P2）。视图：表格视图显示所有项目，看板按状态分组，时间线按日期范围显示"

### 用自然语言描述查询条件

你不需要写 SQL 或了解技术细节——用日常语言描述你要什么就行：

> 💬 "找出上周创建的、还没有指定负责人的任务"
> 
> 💬 "统计这个月每个人完成了多少任务"

### 理解 Status 属性的分组

如果你让 Agent 创建一个带状态的数据库，记得描述每个状态选项属于哪个阶段（待办/进行中/完成）。如果不说，Agent 会按常识判断，但可能和你的预期不同。

## 本章小结

- **数据库** = 数据源（属性结构）+ 视图（展示方式）+ 页面（每条记录）
- **属性类型**丰富：文本、数字、日期、选择、状态、人员、关联、公式、汇总等
- **视图**支持表格、看板、日历、列表、画廊、时间线、图表、地图、表单、仪表盘
- **查询**可以用自然语言描述，Agent 自动处理过滤、分组、统计
- **关联**支持单向和双向，配合汇总可以聚合关联数据
- **链接数据库**可以在不同页面展示同一份数据的不同视角
- 创建数据库时一次说清属性和视图，效率最高
